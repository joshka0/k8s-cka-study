u2l1::gate-order cloze

Front

Complete it
Gate order for a write: authenticate → authorize → [...] → [...] → persist and notify watchers.

Back

Gate order for a write: authenticate → authorize → mutating admission → validating admission → persist and notify watchers.
Mutation runs before validation so what gets validated is the final object. Persistence is last, and only then do watchers learn anything.

u6l3::three-mechanisms discrimination

Front

Discriminate
Scheduler preemption vs kubelet eviction vs API eviction — actor and trigger for each.

Back

Scheduler preemption vs kubelet eviction vs API eviction — actor and trigger for each.
  • Scheduler preemption — removes lower-priority Pods so a pending higher-priority Pod can be placed. Trigger: a pending Pod.
  • Kubelet eviction — terminates Pods under local memory or disk pressure. Trigger: the node itself.
  • API eviction — voluntary disruption, honours PDBs. What a drain uses.

u12l2::ninety-second-answer name_to_definition

Front

Explain it
Give the 90-second Kubernetes architecture answer.

Back

Give the 90-second Kubernetes architecture answer.
Clients declare intent through a policy-enforcing API that persists canonical objects in etcd. Controllers reconcile those objects toward the declared state; the scheduler binds Pods to nodes; kubelets coordinate the runtime, networking and storage that make a Pod real. Services and DNS expose the endpoints that are ready. Every stage is asynchronous, observable and retryable, and the whole system is protected by ownership rules, quorum, flow control and rehearsed recovery.

u10l2::claim-to-mount cloze

Front

Complete it
Claim to mount: PVC → external-provisioner calls [...] → PV created and bound → external-attacher drives [...] → node plugin runs [...] then [...] → container sees the mount.

Back

Claim to mount: PVC → external-provisioner calls CreateVolume → PV created and bound → external-attacher drives ControllerPublishVolume → node plugin runs NodeStageVolume then NodePublishVolume → container sees the mount.
Stage happens once per node; publish happens per Pod target path. Knowing which failed tells you whether the problem is the device or the bind mount.

u8l2::clusterip-timeout name_to_definition

Front

Explain it
DNS resolves but the ClusterIP times out. Trace it.

Back

DNS resolves but the ClusterIP times out. Trace it.
  • EndpointSlices and Service ports — are there ready backends at all?
  • Hit a ready Pod IP directly: if that works, it is Service translation, not the workload
  • Node data plane: kube-proxy rules or BPF maps, and conntrack
  • Routing, MTU, NetworkPolicy
  • Last: is the app actually listening on that port?
A correct data plane delivering to a closed port looks identical from the client.
