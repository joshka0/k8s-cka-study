Why is kube-apiserver the cluster coordination and policy boundary?
It exposes the supported API, applies request policy and conversion, persists canonical objects through etcd, and serves reads and watches. Other components coordinate through this contract rather than storage internals.

Back
API server vs etcd: which owns the public contract, and which persists state?
The API server owns authentication, policy, validation, versioning, conversion, reads, and watches. etcd is the strongly consistent persistence layer behind it; clients should not bypass the API contract.
