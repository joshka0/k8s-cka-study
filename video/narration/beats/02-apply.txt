Stage one. You write a spec — a declaration of what you want, not a set of instructions. kubectl serialises it and sends an HTTP request over TLS to the API server. The API server is the only component that talks to storage. Controllers, the scheduler, the kubelet: none of them read etcd. They all coordinate through this one HTTP contract, which is what lets the API server enforce policy on every write. A controller that reads etcd directly skips authentication, authorisation, admission, validation, conversion and audit in one go.
