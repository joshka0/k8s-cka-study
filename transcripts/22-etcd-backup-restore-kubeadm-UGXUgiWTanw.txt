Now let's talk about something common
restore mistake. These mistakes are very
common in real environments
and also very common in CK exam. First
restoring to existing data directory.
Never restore on top of where liet
always restore to new directory. If you
mix old and new data, the cluster may
not start properly.
Second, forgetting certificates. When
you are using it set ctl you must
provide the correct csert and keys.
Without proper certificates the restore
or health check will fail. Third
not stopping API server the API server
continuously communicate with its set.
If you try to restore while it is
running it can cause a problem. Always
stop the API server first.
Next, using the wrong endpoints. Make
sure you are using the correct set
endpoints in QVDM.
Next,
not updating the ETS AL manifest. After
restoring to a new data directory, you
must update the manifest file to point
to a new path. Otherwise, its set will
still try to use the old directory.
And finally, skipping the health check.
Always check the set health check before
taking a snapshot. If you remember these
points, your restore process will be
smooth and safe.
